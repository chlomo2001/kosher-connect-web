# Adversarial sweep — 2 August 2026

Owner asked for an agent to "go through the whole system trying to do everything
it can and find loopholes". This is that pass.

**Method.** No test data was created. The container holds no secrets (hard rule:
they live only in Vercel), so there is no way to drive the real app end-to-end
from here, and writing junk into Kc-Live to delete later is a worse trade than
reading the code that would accept it. Instead: three adversarial readers over
the whole mutation surface (money, auth/PII, data integrity), each asked to
produce a concrete exploit per finding, cross-checked against the constraints
that actually exist in the database. A loophole only counts when **both** layers
miss it.

**DB backstop, verified against Kc-staging.** RLS is on for all 47 public tables.
The ledger's core invariants are real constraints, not hopes: `unique
(charge_reference)`, `ledger_amount_nonzero`, `ledger_amount_sign` (per-entry-type
sign CASE), an append-only trigger, `numeric(10,2)`, the guarded atomic
`adjust_stock_qty`, and an `idempotency_keys` PK. Stripe webhooks are
signature-verified and event-deduped. Every API route has an auth guard — the
findings below are about what the guards *permit*, not missing ones.

Nothing here was exploited against live data; all findings are read-and-reason.

## Money

1. **MED — ledger idempotency depends on the client sending a token.**
   `pages/api/ledger.js:237`, `pages/api/shop.js:194,275`. With `clientRef`
   omitted the server mints a fresh reference per call, so the unique index
   never fires. Double-click or retry-after-timeout on a £50 payment credits
   £100. The Stripe paths correctly *require* the token (400 without it); the
   ledger and shop paths only hope for it. Fix: require it there too.
2. **MED — card refunds are capped against the original payment, not net of
   prior refunds.** `pages/api/refund-card.js:35-47`. No query for existing
   refund rows and no DB link between a payment and its refunds; only Stripe's
   own ceiling blocks the second full refund. A refund issued from the Stripe
   dashboard leaves no reversal here, and the wallet then overstates credit.
3. **LOW-MED — no upper bound on money-in.** `pages/api/ledger.js:209-215`.
   `charge-card` and `portal/pay` both cap at £5000; this path caps nothing, so
   a fat-finger can mint a wallet credit limited only by the column width — and
   that balance is spendable as goods at the till.
4. **LOW — `custom-charges` `apply` runs before the owner gate.**
   `pages/api/custom-charges.js:41-57`. Any signed-in helper can post a payment
   with a chosen tender, inflating expected cash on the Z-report. No net credit
   is minted, so impact is bounded, but it contradicts the wallet gate.

## Auth, access control, PII

5. **HIGH — `/api/auth/login` has no rate limit and answers as an oracle.**
   `pages/api/auth/login.js:16-60`. Wrong password → 401; correct password →
   200 with a 2FA ticket. Unlimited guesses with an unambiguous success signal.
6. **HIGH — the 2FA lockout can be reset at will.** `lib/auth.js:140-153` keys
   the attempt counter on the *ticket*, so an attacker who has the password
   mints a fresh ticket every five tries and the limit never binds. Each cycle
   also fires an OTP to the owner's inbox. Fix: key on email, and rate-limit
   login.
7. **MED/HIGH — any helper can enumerate every passenger's passport number.**
   `pages/api/bookings.js:121-131`. The list call returns all booking ids with
   passports masked; `?checkin=<id>` returns them unmasked, gated only by the
   bookings tab — which the seeded default helper role includes. One list call
   plus one call per booking walks the whole register. No scoping, no rate
   limit, no audit trail. The owner's decision was "staff doing the check-in may
   see them"; the code grants "any helper may see all of them".
8. **MED — passport-adjacent fields are not masked at all.** Same file, the mask
   strips only the number and expiry; DOB, nationality, issuing country and
   issue date flow to every helper in the ordinary list.
9. **MED — `helperTabs()` fails open.** `lib/auth.js:169-174`: a missing or
   unrecognised `helper_tabs` row returns *all* tabs. A restore or a bad edit
   silently promotes every helper to full access. Should fail closed.
10. **MED — `/api/cron/sweep` accepts GET, so it is CSRF-able.**
    `pages/api/cron/sweep.js:170` has no method check and the session cookie is
    `SameSite=Lax`, which is sent on top-level cross-site GET. Any signed-in
    staff member who clicks a crafted link runs the sweep as themselves: VN
    charges posted, billing dates advanced, bookings completed. Idempotency
    bounds it to billing a period early. Fix: require POST.
11. **MED — `clientIp()` trusts the first `x-forwarded-for` entry.**
    `lib/rateLimit.js:20`. If any hop appends rather than replaces, a per-request
    header gives each request a fresh bucket and the magic-link email throttle
    stops throttling. Pin to the Vercel-specific header.
12. **MED — `CRON_SECRET` compared with `===`.** `cron/sweep.js:176-178`. The
    fail-safe is right (unset secret does *not* open the endpoint to anonymous
    callers), but the comparison should be timing-safe, as `check2faTicket`
    already is.
13. **LOW/MED — the owner bootstrap re-arms if `staff_profiles` ever empties.**
    `lib/auth.js:244-253`. The app cannot empty that table (last-owner guards
    hold), but a direct delete or a restore-to-empty would let the next login
    become owner. Gate it on an env allowlist.
14. **LOW — portal refresh token in `localStorage`** (`pages/portal.js:244`),
    where staff correctly use an httpOnly cookie. **LOW —
    `/api/payment-link` has no tab gate.** **LOW — `/api/documents/download`
    does not scope to a customer**, unlike its portal twin which does.

**Verified clean:** no portal IDOR (every portal route derives identity from the
token and never accepts a customer id); no secret in the browser bundle; bulk
PII exports are owner-only and carry no passport data; CSV has a
formula-injection guard.

## Data integrity

15. **HIGH — deleting a customer can destroy rentals and SIMs and then fail.**
    `lib/tableStore.js:130-143`: three sequential deletes, no transaction. Tasks,
    virtual numbers, repairs and bookings reference `customers` with no
    `ON DELETE`, so one open auto-task makes the third delete fail *after* the
    rentals and SIMs are gone — no ledger reversal, and the customer still
    exists. Same path from the ELID merge.
16. **HIGH — a bad date wipes a booking's passengers.**
    `pages/api/bookings.js:400-419` deletes all passenger rows before inserting
    the new ones, unwrapped. A malformed date fails the insert and the rows are
    gone — including passport numbers helpers cannot re-enter, because reads
    mask them.
17. **HIGH — the customer phone unique index is decorative.**
    `lib/mappers.js:41-47` never routes through `ukPhone`, so `+44 7911 123456`,
    `+447911123456` and `07911 123456` split three different ways and create
    three "unique" rows for one person. Duplicate detection matches on name
    only, so it won't surface them either.
18. **HIGH — Israeli numbers are silently converted to UK.**
    `lib/ukPhone.mjs:32` treats any 10–12 digit string starting `0` as UK, so
    `0525115445` becomes `+44525115445`. Given this customer base that is a live
    corruption, and it reaches the VCF export that loads the shop phone.
    Related: `+44 (0)161 …` keeps the trunk zero inside the `+44`.
19. **HIGH — re-collecting a cancelled repair loses the charge.**
    `pages/api/repairs.js:96-189`. Status is a membership list, not a state
    machine: Collected → Cancelled → Collected leaves the reversal in place and
    the re-charge deduped away, netting zero on a repair actually collected.
20. **MED — renaming a shul silently unlinks its wallet.**
    `pages/api/kol-torah.js:120` writes `customer_id` unconditionally, so a save
    that only changes the name nulls the link and every later settlement posts
    no ledger rows at all.
21. **MED — customer PUT is an unbounded read-modify-write.**
    `pages/api/customers.js:36-44`. No field whitelist, no length cap, and two
    staff editing one customer lose the first edit.
22. **MED — British dates are stored as American.** Postgres `DateStyle` is
    `ISO, MDY`, and several routes pass raw strings into `date` columns, so
    `08/07/2026` (8 July) lands as 7 August. Affects travel dates, passenger
    DOBs, task due dates and travel authorisations.
23. **MED — Hebrew service names collide.** `pages/api/services.js:33` slugs to
    ASCII only, so two different Hebrew repair names both become `repair-` and
    the second save fails with an unusable "Storage error".
24. **MED — one bad item discards a whole array save** (phones, rentals, sims),
    and the client fire-and-forgets, so the loss is silent.
25. **MED — the CSV formula guard mangles every phone number.**
    `pages/api/export-csv.js:29-33` — the `+` case means the whole phone column
    ships with a leading apostrophe.
26. **MED — an unvalidated email can fan a receipt out to a second address**,
    because nodemailer parses a comma-separated `to` and the address is never
    validated on the way in.

Plus lows: travel-auth has no range check and no ownership check on delete,
`automations` accepts a blank threshold as 0, `customers` POST accepts `{}`.

## Fixed 2 Aug, late night — the recommended first six

Findings **5, 6, 7, 15, 16, 18** are fixed on the dev branch (commit
`258583e`), in the order this doc recommended:

- **5** — `/api/auth/login` now has a per-IP rate limit (10 burst, 3/min) and
  a per-email lockout (8 fails / 15 min). The oracle still answers, but
  guessing against it is no longer free.
- **6** — the 2FA attempt counter keys on the **email**, windowed at 15 min;
  minting a fresh ticket no longer resets it.
- **7** — the unmasked `?checkin=` view is throttled per staff member
  (15 reads / 10 min — a family's check-ins fit, walking the register
  doesn't) and every unmasked read writes an `[audit]` line to the runtime
  log. The tab gate stays.
- **15** — `deleteCustomer` pre-checks every dependent table (tasks, VNs,
  repairs, bookings, sold phones, shop sales, service orders) and refuses
  with a named list *before* touching rentals/sims. No more partial deletes.
- **16** — passenger replace validates all dates up front (400, nothing
  touched) and inserts the new rows **before** deleting the old ones, so a
  failed insert can no longer destroy passport data.
- **18** — `normalizeUkNumber` sends Israeli 05x mobiles (10 digits) and
  0-2/3/4/8/9 landlines (9 digits) to `+972`; both shapes are unreachable by
  any real UK number. A trunk zero inside `+44`/`+972` is dropped. Pinned in
  the converter test net.

## Fixed 3 Aug, tranche 2 — remaining HIGHs + money + auth MEDs

Findings **1, 2, 3, 4, 9, 10, 11, 12, 17, 19** fixed on the dev branch:

- **1** — `/api/ledger` and the shop sale now REQUIRE the idempotency token
  (400 without it), like the Stripe paths always did. The till and wallet UI
  always send one, so only retries-without-token change behaviour — which is
  the point.
- **2** — card refunds cap against what's LEFT of the payment (prior refund
  rows are summed), and the refund reference now embeds the payment intent
  (`STRIPE-REFUND-<pi>-<refund id>`) so the link is queryable. Refunds issued
  from the Stripe dashboard still leave no ledger row — that wants a
  `charge.refunded` webhook handler, noted as a follow-on.
- **3** — the ledger path gets the same £5,000 per-entry ceiling as
  charge-card and portal/pay; larger amounts are recorded as two entries.
- **4** — `custom-charges` `apply` now requires the tab whose record it
  charges (rentals/sim) instead of running before the gate.
- **9** — `helperTabs()` fails CLOSED: a missing or empty setting row now
  disables helper writes (reads and owners unaffected) instead of granting
  every tab.
- **10** — staff-invoked sweeps must be POST (the app already POSTs); GET
  survives only for Vercel Cron's bearer-authenticated calls. Kills the CSRF.
- **11** — `clientIp()` prefers the platform-set `x-vercel-forwarded-for` /
  `x-real-ip` headers; client-appendable `x-forwarded-for` is local-dev only.
- **12** — `CRON_SECRET` compares timing-safe, matching `check2faTicket`.
- **17** — `splitPhone` canonicalises through `normalizeUkNumber` before
  splitting, so every format of one number lands on ONE
  (phone_country_code, phone_number) pair and the unique index binds. Typed
  columns now hold bare digits; the app string comes back in the owner's
  display grouping. Existing rows keep their old split until next save — the
  drift detector will show them, which is accurate.
- **19** — repair status: **Cancelled is terminal** (409 with "open a new
  repair"). The money references are one-shot, so the
  Collected→Cancelled→Collected cycle that netted a collected repair to £0
  can no longer be entered.

Still open: **8** (passport-adjacent fields unmasked), **13/14** (lows),
**20–26** + lows (data integrity, incl. the `DateStyle MDY` date hazard #22,
which wants its own careful pass across every date-writing route).

## What was fixed in this pass

Only the public-page layout defects, because they were unambiguous and
self-contained. The findings above are code changes with money and auth
blast-radius and want the owner's call on sequencing — recommend 5, 6, 7, 15,
16, 18 first.

- `/welcome` nav overflowed the viewport at **every** desktop width. The link row
  is a fixed run of nowrap items needing 1281px against the 1123px the container
  can ever offer, so the document carried a horizontal scrollbar and "Message
  us" sat off-screen. The 960px breakpoint meant 961–1280 was permanently
  broken. Verified fixed at 360/390/414/640/768/1024/1279/1280/1366/1440/1920 —
  document width now equals viewport width at every one.
- The language switcher was being crushed to **2px** on a phone: it was a
  shrinkable flex item. Hebrew and Yiddish speakers could see it but not hit it.
  Now `flex:none`, 81px.
- The fixed theme toggle floats over the nav at every width and was sitting on
  top of the "Message us" button, clipping the word. It now has a reserved lane.
