## Remaining confirmed findings — next-cycle worklist (code fixes)

Ranked by value. All verified; none shipped yet.

1. **Booking & service-order idempotency race (medium).** `pages/api/bookings.js`
   and `service-orders.js` do non-atomic check-then-insert, so a concurrent
   double-submit creates a duplicate uncharged row (the ledger dedupes the charge
   but not the row; the loser still reports `chargePosted=true`). Fix: adopt the
   shop `db.claimKey` pattern (`BOOKING-<ref>` / `SVC-<ref>`).
2. **Cancelling a booking/repair never reverses its charge (medium).** Booking
   creation posts `-(price+fee)`; PUT→Cancelled posts no reversal and nothing
   prompts one, so a cancelled unpaid booking leaves permanent arrears that the
   sweep then chases. Repairs same class. Fix: post an idempotent compensating
   credit on cancel, or return a flag that opens the wallet modal pre-filled.
   (KC already auto-reverses on rental void / SIM delete — this is an
   inconsistency, not a policy.)
3. **Cash-up & dashboard "today" use UTC, business day is Europe/London (medium).**
   BST 00:00–01:00 till movements land on the wrong Z-report and persist a wrong
   `till_counts.expected/variance`. Already tracked in `REVIEW-2026-07-16.md` A3
   / BACKLOG P2. Fix: reuse the sweep's `localDate()` and zone-anchor the query
   bounds. Touches `cashup.js` and `ledger.js` day-window defaults.
4. **Card-on-file human-retry double charge (client half) (medium/HIGH).** Server
   half shipped (ambiguous errors now say "do NOT retry"). Remaining: `chargeCardOnFile`
   in main.js mints a fresh `kcRef()` per attempt, so a retry after an ambiguous
   failure is a new Stripe idempotency key = a second real charge. Fix: mint the
   ref once per (customer, amount) and reuse it on retry.
5. **Modal focus management (medium, a11y).** No close-time focus restoration
   anywhere; `kcConfirm` (the charge dialog) sets no initial focus, so Enter can
   re-fire the trigger behind the overlay and orphan the first promise. Fix: save
   `document.activeElement` on open, restore on close; focus Cancel in kcConfirm.
6. **Customer add/edit modal — no input labels (medium, a11y).** Every field in
   `components/AppShell.js` is an unassociated `<label>` (no `htmlFor`), the
   country-code select has none, error spans aren't `aria-describedby`. Fix:
   `htmlFor`/`aria-label` + toggle `aria-invalid` in main.js's `setErr`.
7. **Unbounded reads on growing tables (medium).** Revenue report sums every
   ledger row since `from`; dashboard + sweep load all customer_balances/customers
   with no limit and assume completeness — past PostgREST's 1000-row cap they
   silently truncate (wrong totals, a debtor gets no BALANCE task). Fix: aggregate
   money in a Postgres function/view; page the sweeps; assert when a page returns
   exactly the cap.
8. **512KB unminified `public/main.js`, no long-cache (medium, perf).** Served
   `max-age=0`, never minified/hashed. Fix: prebuild esbuild/terser →
   `main.<hash>.js`, `next.config.js` `headers()` `immutable` cache. (~40–60%
   smaller, near-instant repeat loads.) Pairs with caching `/fonts/*` + images.
9. **Welcome canvas double-projects every point per frame (medium, perf).** ~8,700
   trig projections/frame. Fix: project each point once (reuse the `vis` flag),
   optional ~30fps cap.
10. **Test-gap lows worth pinning:** `parseSmsBackupXml` silently drops any SMS
    body containing a raw `>` (regex stops at first `>`; fix the regex to consume
    quoted spans + add the failing test); `serviceOrderTotal` treats `repeat=0`/`''`
    as a free tier (decide contract + assert); `priceFromDays` cap-below-minimum
    and all-free-day branches untested; `advanceOneMonth` non-padded-date
    passthrough untested; `zipLite.unzip` never verifies CRC-32.

Plus the rest of the RTL/a11y lows (physical→logical CSS properties sweep,
`font-synthesis: none` for Hebrew via `:lang()`, welcome `<title>`/meta + nav
aria-labels untranslated, glass-panel contrast, Inter weight-900-unused/600-missing).

## Research digest — high-caliber ideas by angle (ranked, with sources)

Full detail in the workflow transcript; the standouts:

### Security (2026)
- Sensitive env vars + rotation (see owner item 3). — Vercel Apr-2026 incident KB.
- Off Next 14 (owner item 4).
- Migrate the legacy `service_role` JWT to a revocable `sb_secret_` key (+
  asymmetric JWT signing so `kc_session` can be verified locally instead of a
  `/auth/v1/user` round-trip per request). <https://supabase.com/docs/guides/getting-started/migrating-to-new-api-keys>
- `__Host-kc_session` cookie prefix + `SameSite=Strict` (OWASP session cheat sheet).
- RLS deny-by-default backstop on every public table + scheduled advisor runs
  (the `get_advisors` MCP tool is already wired in — run it monthly via a Routine).

### POS / shop UX (community-fit for a chasidish, low-tech clientele)
- **Keyboard-first till** — number-row hotkeys for the ~10 top items, Enter-to-tender,
  always-focused scan box. Small work on existing barcode + Shift+? plumbing.
- **Undo over confirm at the till** — void-last-line + 30s undo toast (writing a
  compensating ledger entry), keep confirms only for refunds/deposit release.
  NN/g: confirmation dialogs get habituated; undo prevents more errors.
- **Reprint/resend any past receipt** — paper → SMS → email order (kosher phones
  are SMS/voice), marked COPY. Trust moment; KC has receipts + SMS-draft infra.
- **Blind cash-up** — count-first (expected hidden), auto-flag variance, reason
  note over threshold. Protects family/community trust, not just cash.
- **Portal + printed statement** — one big "You owe / In credit £X" card + a
  bank-passbook-style dated running statement, English + optional Yiddish/Hebrew.
  Most customers will only ever see the paper statement — design it to utility-bill
  best practice (amount due + date huge, plain language).
- **Proactive low-balance/due nudges over SMS** (HOLD-gated drafts) + a printed
  "account note" slip with the next receipt. Dignified arrears-chasing.
- Offline-tolerant till (outbox + background sync) — largest item; real resilience.

### RTL typography
- Set `lang`/`dir` on the **html element** (`_document`/`_app`), not just a wrapper
  div — fixes SR voice, scrollbar side, and enables `:lang()` selectors.
- Bidi-isolate every embedded LTR token (£ ranges, phone numbers, Latin brand
  names) in RTL dict strings via `<bdi>`/`<span dir=ltr>` (started this cycle in
  the portal; extend to dict content + welcome).
- `*:lang(he),*:lang(yi){ font-synthesis:none; letter-spacing:0 }` — David Libre
  has no italic; faux-bold/italic distorts Hebrew. Needs the html-lang change first.
- Force LTR on email/tel/url inputs inside RTL forms (done for the portal email).
- Migrate ~37 physical left/right CSS props to logical properties (`margin-inline-*`,
  `text-align: start/end`) + a stylelint `use-logical` rule.
- Strip Unicode bidi control chars (U+202A–202E, U+2066–2069) from imported
  contact/VCF text (trojan-source spoofing in receipts/exports).

### Next.js pages-router perf (Vercel)
- Long-cache `/fonts/*` + images via `next.config.js` `headers()` (immutable).
- Minify + content-hash `main.js`, serve immutable (see finding 8).
- Preload `main.js` + the primary Hebrew woff2 from `_document`.
- Keep self-hosted `@font-face` (don't migrate to `next/font`); add a `size-adjust`
  fallback face to kill swap CLS.
- INP hygiene inside main.js (break long tasks, `scheduler.yield()`), measured
  first — INP is 2026's most-failed CWV and a big vanilla-JS SPA is most exposed.

## Refuted (recorded so they aren't re-raised)

- "Helper can read the full customer base via GET" — **by design & UI-disclosed**;
  reads are open to signed-in staff (the customer card cross-reads many features),
  sensitive fields already masked/encrypted, bulk exports are `requireOwner`.
- "Render-blocking Google Fonts in the staff shell" — Next 14's automatic font
  optimization inlines the CSS and injects the gstatic preconnect at build; verified
  in the served HTML. (Becomes real if we upgrade to Next 15 — note it then.)
- "Sweep will time out before VN billing (no maxDuration)" — rests on the legacy
  10–15s default; Vercel Fluid compute defaults to 300s. Batching the N+1 loops is
  still legitimate hardening, but not the claimed defect.
